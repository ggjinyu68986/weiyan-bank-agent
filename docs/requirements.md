# 微言 · AI银行智能体 — 技术方案（requirements.md）

- 版本：v0.1（2026-09-26 草案，待 9/27 启动会定稿）
- 赛题：2026 FinTechathon AI 赛道 · 银行 AI 智能体

---

## 1. 目标

用户用自然语言描述需求 → Agent 自主完成**意图理解 → DAG 任务规划 → 权限门 → 执行 → 审计**，覆盖 6 大场景，安全机制（权限分级/幻觉防护/注入防御/操作审计/异常熔断/沙箱）全落地，通过初赛自动评测。

## 2. 总体架构（四层 + 横切）

```
交互层   frontend/   聊天 UI、确认卡片、MFA 交互、审计面板
编排层   backend/agent/   意图理解 → DAG 规划 → 工具调度 → 权限门 → 审计
能力层   backend/tools/   工具集：转账/账单/理财/卡片/订阅/跨场景联动
数据层   backend/bank_sim/ Mock Bank（账户/交易/卡/理财/订阅/事件）+ SQLite
横切    权限引擎 · 安全（注入/幻觉/熔断）· 审计日志
```

## 3. 技术栈决策表

| 模块 | 建议选型 | 理由 | 备选 |
|---|---|---|---|
| 语言/环境 | Python 3.12 + uv | Agent 开发生态成熟、依赖管理快 | — |

## 4. 为什么自研编排（答辩核心论点）

1. **权限门必须在每一步执行前强制经过**——现成框架会把决策链路封装在黑盒里，评委问"权限判定在哪一层"答不上来。
2. **审计要完整记录"意图→风险级→确认/MFA→结果"**——自研才能保证链路可回溯。
3. 参考 OpenClaw 等开源智能体的思路，但**核心编排层自研**，工具层可复用开源。

## 5. Mock Bank 设计要点

- 实体：用户 / 账户 / 交易 / 卡片 / 理财产品 / 订阅协议 / 事件（生日等）
- **"测试用户"完整画像**：工资入账、房租、订阅清单、消费习惯（账单分析/异常识别全靠它）
- 接口：余额 / 明细 / 转账 / 申购赎回 / 卡操作 / 订阅 / 锁定资金 / 定时任务
- 所有接口返回结构化结果 + 唯一 **execution_id**（幻觉防护：Agent 只能回显工具真实返回值）

## 6. 权限分级（绿黄红）

- **操作注册表**：每个工具登记 `risk_level` + 限额
- 绿（自动）：余额查询、交易明细、账单分析、收益查询
- 黄（确认）：小额转账（日累计≤1000）、订阅取消、虚拟卡申请
- 红（强验证）：大额转账（日累计>1000）、密码修改、挂失解挂、理财申购 → 短信/人脸/U盾 MFA
- 日累计限额追踪 + 超限自动升级（黄→红）

## 7. LLM 成本策略

- 日常开发/评测：豆包（低价/免费额度充足）
- 演示/答辩：旗舰模型
- 每轮调用：超时 + 重试 + 降级处理
