# 微言 · AI银行智能体 — 技术方案（requirements.md）

- 版本：v2.0（2026-09-26 定稿 · 单人作战 · **一等奖设计标准**）
- 赛题：2026 FinTechathon AI 赛道 · 银行 AI 智能体

---

## 1. 设计原则（一等奖导向）

1. **可评测**：以"初赛自动评测"为第一验收标准——6 场景跑通、安全违规 0、对话轮数可控。
2. **可答辩**：每个技术决策都要经得起评委追问 3 层（为什么这么选 / 怎么实现的 / 出问题怎么办）。
3. **可演示**：现场不翻车——零构建、离线兜底、备用模型、录屏备选。
4. **可审计**：关键操作全留痕，答辩用证据说话（审计面板现场展示）。

## 2. 总体架构

```
交互层   frontend/      类IM聊天页、确认卡片、MFA弹层、审计面板
编排层   backend/agent/ 意图理解 → DAG规划 → 工具调度 → 权限门 → 审计
能力层   backend/tools/ 工具集：转账/账单/理财/卡片/订阅/跨场景联动
数据层   backend/bank_sim/ Mock Bank（账户/交易/卡/理财/订阅/事件）+ SQLite
横切     权限引擎（数据驱动）· 安全（注入/幻觉/熔断）· 审计日志 · 沙箱
```

## 4. 为什么自研编排（答辩核心论点）

1. **权限门必须在每一步执行前强制经过**——现成框架把决策链路封在黑盒，评委问"权限判定在哪一层"答不上来。
2. **审计要完整记录"意图→风险级→确认/MFA→结果"**——自研才能保证链路可回溯。
3. **薄封装**：LLM 调用、重试、解析自己写，核心编排 <1000 行，代码质量完全可控；不引入 LangChain/LangGraph 等重框架（黑盒、难讲、易被质疑套壳）。
4. 借鉴 OpenClaw 等开源项目的**插件化思路**（工具即插件），并在文档中大方注明——显示行业视野。

## 5. 核心设计（一等奖导向 7 模块）

### 5.1 权限引擎（数据驱动，非硬编码）
- **操作注册表用配置定义**（YAML/JSON）：工具名 / 风险级（绿黄红）/ 日限额 / MFA 要求。
- 引擎 = 纯函数：`(工具, 参数, 用户状态) → {允许自动 / 需确认 / 需强验证}`——可单测、可画状态机、答辩可直接贴图。
- 日累计限额追踪 + 超限自动升级（黄→红）。

### 5.2 工具协议（强校验）
- 统一 `ToolCall` schema：`{tool, params, request_id}`。
- 系统侧用 pydantic 强校验参数（类型/范围/白名单），LLM 无自由发挥空间——这是注入防御的第一道闸。

### 5.3 LLM Provider 抽象（可插拔）
- 统一接口：`chat(tools, messages) → 结构化结果`。
- 实现：豆包默认 + GPT/Claude 适配器；统一超时 / 重试 / 降级 / 缓存。

### 5.4 Mock Bank（仿真银行，自动评测的打点对象）
- 幂等（同 request_id 不重复执行）、**金额用分存储（禁浮点）**、每个结果带唯一 `execution_id`。
- 接口按真银行风格：`POST /api/v1/transfer` 等；可注入模拟延迟与异常（测试熔断用）。

### 5.5 审计链路（全链路留痕）
- 事件流：`user_msg → intent → plan → risk_decision → confirm/mfa → result` 逐条落库。
- 前端审计面板实时展示——答辩现场演示的亮点。

### 5.6 沙箱（双轨）
- 轨A Docker：受限镜像 + 网络隔离。
- 轨B 纯进程：subprocess + 资源限制 + 超时 + 白名单——现场无 Docker 时保命。

### 5.7 评测 harness（一等公民，不只是测试）
- 场景 DSL：YAML 定义对话脚本（用户说什么 → 期望 Agent 做什么 → 断言）。
- 输出报告：完成率 / 安全违规数 / 平均轮数 / 超时项 → MD/JSON 双格式。
- 它既是自测工具，也是交付物里的"测试用例"文档——盲审加分项。

## 6. 前端设计要求（视觉规范，10/20 定稿）

- **类 IM 聊天页**：覆盖赛题"APP、IM 等渠道"的展示需求。
- **三色权限系统贯穿 UI**：绿=自动执行徽标 / 黄=确认卡片（展示操作详情）/ 红=MFA 弹层（短信码/人脸/U盾 模拟）。
- 流式打字效果 + 执行状态动画；报表用 ECharts 图表。
- 独立**审计面板页**（实时日志流）。
- 视觉：银行质感（10/20 二选一定稿：深色科技风 / 清爽浅色）。

## 7. LLM 成本与稳定性策略

- 日常开发/评测：豆包（低价/免费额度充足）；演示/答辩：旗舰模型。
- 每轮调用：超时 + 重试 + 降级；演示备离线脚本兜底（LLM 挂也能放录屏）。

## 8. 技术决策定稿（v2.0）

| 决策项 | 结论 |
|---|---|
| 前端 | 纯 HTML/JS 单页 + ECharts CDN（零构建，演示保命；视觉按 §6 规范） |
| 部署 | Docker Compose 本地；决赛现场无 Docker 走纯进程沙箱轨 |
| git | main 直推 + 关键节点 tag；每晚 commit |
| 节奏 | 每日自检：跑 harness + commit + 录 10 分钟素材 |
| 分工 | 单人作战；组队后按模块拆分 |

## 9. 版本记录（自检升级说明）

- **v1.0**：首版定稿（单人可执行）。
- **v2.0**：按一等奖标准自检，修复 3 处"够用但不够获奖"的问题，升级 5 点：
  1. 权限策略**数据驱动**（配置注册表），避免硬编码——答辩与盲审直接加分；
  2. 评测 harness 升级为**交付级模块**（DSL + 双格式报告）——"测试用例"成为作品资料亮点；
  3. 前端**视觉规范显式化**（三色权限系统/确认卡/MFA/审计面板），防止纯 HTML 做丑拉低演示分；
  4. 沙箱**双轨**（Docker + 纯进程兜底），消除决赛现场环境风险；
  5. **LLM Provider 抽象 + 工具协议强校验**，不绑定厂商、防套壳质疑。

> 自检结论：大方向（自研编排 + FastAPI + SQLite + 零构建前端）不变——它既是单人 5 周可执行的最优解，也天然契合评委口味；升级点全部落在"证据与质量"层面，不增加不可控工作量。
